# 竹知了 Blender 5.2 Geometry Nodes 经验总结

## 1. 最终稳定架构

工程采用四棵节点树分层：

1. `GN_甩杆`：只负责甩杆局部建模，不固定对象世界位置或旋转。
2. `GN_蝉体`：只负责竹筒、竹膜、绳结、眼、翅、脚等本体建模。
3. `GN_装配`：参考仓库的程序化展示装配，用于蝉体、甩杆和松香线的静态/演示组合。
4. `GN_绳系物理`：当前主要物理实现；Simulation Zone 保存单点几何和速度，杆端 Empty 是动态锚点。

对象职责：

- `甩杆`：用户直接操作的独立对象，原点位于世界中心。
- `杆端绳结`：甩杆子对象，向 `GN_绳系物理` 提供动态锚点。
- `物理竹知了`：无父级，由 Simulation Zone 独立积分。

## 2. 原仓库事实源

真实物理事实源是 `zhuzhiliao/index.html`，不是 `3d/model.js`。

核心模型：

```text
2D 单质点
+ 重力
+ 只拉不推的弹性绳
+ 绳径向阻尼
+ 空气阻力
+ 1/240s 固定步长
+ 半隐式 Euler
```

`3d/model.js` 主要消费外部 `pose`，负责模型摆位、翅膀、绳形和竹膜发光。它的 `whirl` 模式是视觉演示，不应当被误认为主站真实物理。

## 3. 当前稳定物理实现

稳定版 `GN_绳系物理` 保存：

- `Geometry`：单点质点；
- `速度`：Vector 状态。

每帧执行：

```text
绳向量 = 锚点 - 质点
伸长 = max(距离 - 绳长, 0)
张力 = normalize(绳向量) × 伸长 × 有效刚度
阻力 = -速度 × 阻尼
加速度 = 张力 + 阻力 + 重力
新速度 = 速度 + 加速度 × Delta Time
新位置 = 位置 + 新速度 × Delta Time
```

其中 `max(伸长, 0)` 是“绳只拉不推”的关键。

## 4. Blender 5.2 兼容性要点

- `Mesh Cylinder` 的 `Fill Segments` 最小值为 1，不能用 0 制造开口。
- 开口竹筒应使用 `Top OR Bottom → Delete Geometry(FACE)` 删除端盖。
- Math 节点使用 `ShaderNodeMath`。
- `Curve Line` / `Curve Circle` 的旧节点类型已变化，必须按 5.2 可用类型构建。
- 默认 Principled BSDF 不应按英文节点名查找，应按 `n.type == 'BSDF_PRINCIPLED'`。
- `bpy.ops.xxx({dict_override})` 已不可用，改用 `bpy.context.temp_override(...)`。
- Blender 5.2 Action 采用 layered API；F-Curve 应遍历 `action.layers → strips → channelbags → fcurves`。
- Geometry Nodes 修改器不支持按旧方式写任意 IDProperty；参数应直接暴露为 Group Input。

## 5. 物理与对象控制经验

### 甩杆必须保持独立

不要把甩杆和蝉体合并为同一个运动对象。甩杆的 Object Transform 应由用户控制，GN 只处理局部建模。

### 关键帧会覆盖手动控制

甩杆绑定 Action 后，手动旋转虽然会瞬时改变锚点，但时间轴刷新会恢复关键帧值。若目标是手动控制，应解除当前 Action；循环动画可复制为带 Fake User 的备份 Action。

### Simulation 需要跨帧输入

单帧瞬间改变锚点只能得到新的静态约束。要看到惯性，必须在多个连续帧中移动锚点并顺序播放/计算。

### 缓存必须主动清理

修改 Simulation Zone 后，旧缓存可能继续显示旧轨迹。验证前应清理 Simulation Nodes Cache，再从起始帧顺序计算。

## 6. 绳子与膜孔连接

参考模型的绳结位于蝉体局部约：

```text
(0.24, 0.998, 0)
```

它是设计上的偏心连接，不应强行放到膜面中心。

连接的可靠原则：

- 绳子起点和蝉体膜孔必须引用同一个模拟质点；
- 旋转蝉体时，需要同步旋转膜孔局部基准并补偿平移；
- 不要仅靠画面判断，应单独评估 Simulation 点、绳几何和蝉体几何，计算真实空间距离。

Blender 5.2 中，复杂字段经过多层 Vector Math 后接 Geometry Transform 可能出现难以察觉的上下文问题。更稳妥的做法是把局部膜孔归零和世界质点平移拆为两个明确的 Transform。

## 7. 已踩过的坑

- 使用空 Action：播放时甩杆完全不动，杆端锚点各帧一致。
- 严格竖直且绳结偏心过小：绕杆轴旋转时锚点圆周太小，物理响应不明显。
- 用父子级/Driver 直接复制位移：得到同步跟随，不是惯性模拟。
- 在 Simulation Zone 一次增加大量状态：缓存和状态接口容易失效，曾导致空几何。
- Repeat Zone 嵌套 Simulation Zone：在当前 Blender 5.2 会话中没有可靠推进，不应保留“节点看似正确、实际不动”的实现。
- 直接使用系统 `open`：可能调起默认 Blender 4.4.3；本项目必须通过 MCP 在 Blender 5.2 会话中加载文件。
- 用包围盒或整体 PCA 判断朝向：翅膀和脚会污染结果，应检查筒体主轴或直接检查旋转链。

## 8. 验证清单

每次修改后至少检查：

1. Blender 版本是 5.2.x，文件路径正确；
2. `杆端绳结.parent == 甩杆`；
3. Object Info 引用 `杆端绳结`；
4. `物理竹知了` 无父级；
5. Simulation 状态项数量与预期一致；
6. 修改器接口仍可见且参数已接线；
7. 清缓存后从第 1 帧顺序计算；
8. 多个抽样帧都有非空几何；
9. 锚点移动时蝉体质心存在滞后，而不是瞬移；
10. 绳端与膜孔使用同一模拟点；
11. 保存后 `bpy.data.filepath` 与目标文件一致。

## 9. 节点整理规范

- 用编号 Frame 表达计算顺序，如 `01 · 绳张力`、`02 · 阻力与重力`。
- Frame 颜色只表达职责，不表达数值状态。
- 节点 label 写物理意义，节点内部 name 尽量保持稳定，避免脚本引用失效。
- 整理时只改 Frame、label、颜色和位置；不要同时修改运算、参数和连线。
- 整理前后对比节点数、连线数、接口及跨帧评估结果。

## 10. 可复用节点组边界

当前值得保持或抽取的节点组：

- `GN_甩杆`：独立局部建模，可被装配或物理场景复用；
- `GN_蝉体`：本体建模和翅角接口，可复用在静态、展示和物理版本；
- `GN_绳系物理`：物理状态必须保持在同一核心组中，不建议拆散 Simulation Zone；
- 膜孔朝向补偿：适合抽成通用偏心挂点对齐组；
- 单向弹性绳力：适合抽成纯数学组，但输入输出必须保持标量/矢量明确；
- 绳曲线几何：适合抽成纯展示组，与物理状态分离。

不建议把每个模型零件拆成独立节点组。节点层级过深会增加字段上下文、材质槽和 Blender 5.2 调试成本。

## 11. 锁定绳长开关

`GN_绳系物理` 增加布尔接口 `锁定绳长`：

- 关闭：沿用原弹性位置和速度，会伸长并产生回弹；
- 开启：将预测位置投影到以杆端为球心、绳长为半径的球面；
- 同时计算 `dot(v, dir)` 并从速度中减去径向分量，只保留切向速度；
- 这样不是简单增加刚度，而是刚性距离约束，因此不会发生弹簧式径向回弹。

验证时不能只修改节点组接口的 `default_value`。Blender 5.2 已存在的修改器实例可能保留自己的接口值；应临时用 Boolean 常量直接驱动 Switch，或在修改器面板中切换后清缓存验证。

## 12. 后续建议

稳定版优先保证可编辑与可理解。若继续复刻原仓库固定子步、径向阻尼、`rps/taut/active`、翅膀和发光，建议在稳定文件副本中逐模块实现，每完成一个模块就清缓存、跨帧验证和保存检查点，避免一次性改造整个 Simulation Zone。
